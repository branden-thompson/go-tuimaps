## P1 — Fields over water, per overlay (L-1.1 to L-1.4)

| Task | Commit | The test first | Learned |
|---|---|---|---|
| P1.1 `Grid.OverWater` and `Image.MaskedByWater` carried to the scene; the `Input` flags removed | this commit | `TestAFieldStopsAtTheShoreByDefault`, `TestHostCanFlipEither`, `TestContoursFollowTheirFieldOverWater`, `TestAChangedWaterChoiceRedraws` (`water_test.go`), `TestAMaskedImageStaysOffTheSea` (`internal/render`); `TestWaterNeverMasksImage` kept. They failed to compile on the missing field, then passed with the change | **The renderer's water flags could not be reached from the public API:** v0.2.0 had them on `render.Input` only, and nothing set them. Each overlay now carries its own choice: the field from hand-in, the image's mask set on the picture as the store hands it out, so a picture shared between maps (`Classified`) never carries another map's choice. A rain grid is drawn over the sea whatever `OverWater` says (A-1). Two measures were wrong at first and were corrected: `groundsOf` counts colour runs, not cells, so a masked image showed more runs (21) than an unmasked one (19); `cellsIn` counts cells. And `momentFrame` renders 80 × 24 whatever the map's size, so the first sea box was out of view. Beside an image a field is drawn as faint lines (L-15.3), so the cross-check compares frames instead of counting band colours. Specimens unchanged: the defaults hold |
| NFR-2 The mutant harness (A-2) | this commit | `TestEveryMutantFindsItsLine`; `TestEveryMutantIsKilled` (tag `mutants`), the gate's new full-lane leg | **Its first run reported every mutant as surviving, which was the harness's own bug:** `goIn` returned the output buffer before running the command (Go evaluates `return buf.String(), cmd.Run() == nil` left to right), so no output ever held `--- FAIL`. Fixed; m001 to m005 are then killed. **m006 first survived, correctly:** `Set` raising the overlays' count is not what makes a changed choice redraw, because the field's new classification landing raises the version too. It was re-pointed to the guard that does hold L-1.4, frame reuse comparing the overlays' version, and is killed. Six mutants, about 17 s |
| A-3 The full gate's fuzz finding: a polygon ring left open | this commit | `TestAPolygonRingIsClosedByClosePath` (`internal/mvt`): a ring left open by the next ring's MoveTo, and one left open at the end of the geometry, each refused; two closed rings kept. It failed on both open cases, then passed | **P1's first full gate failed on `FuzzAgree` (`tools/oracle`), a finding older than P1** (the decoder is untouched since v0.2.0). The input breaks the tile format, so ours now refuses it (A-3) rather than the oracle taking an exemption. With the fix the oracle passes, and 90 s more of fuzzing (1.18 million inputs) found nothing. The failing input stays as a seed. Mutants m007 and m008. **To run the oracle by hand, use the gate's workspace:** with `GOWORK=off` the oracle module tests the published v0.2.0 from the module cache, not this tree. The failed run counts against M6's five consecutive runs (P7.2) as an attributed failure. **The second full run failed on `FuzzAgree` again, with a new input** (a negative zig-zag rank, A-4), and ten minutes of local fuzzing then found a third (a ring of two LineTo commands, the same misreading as the first, so A-3 was widened). Each fix test first (`TestANegativeRankIsNoRank`, a third case in `TestAPolygonRingIsClosedByClosePath`), each input kept as a seed, mutants m009 and m010. Both runs count against M6 as attributed failures |
