## The quality pass after watchpost's UAT-1 (2026-10-11)

watchpost's HUM LEAD asked for a performance, DRY and code-quality pass across the three projects before the next batch, with behaviour and UI unchanged. A read-only review of v0.2.0 to `v0.3.0-rc.1` raised seven findings; five are done here.

| Change | The test first | Learned |
|---|---|---|
| Water asked once a frame (NFR-1) | `BenchmarkGlobeFieldPan` (new: a one-cell pan over the world under a 2° MUF field drawn as lines, continued over water and stopping at the shore), run on the old code first; `TestTheWaterAskedOnceAFrameIsThePaintersAnswer` (`internal/render`: every cell's held answer is the painter's, after the view moves too) | **The water test counts a cell's dots and, at a tie, its neighbours', and a field asked it of every dot of its contours and every cell of its fill, a field continued over water included.** Each cell's answer is now asked at most once a frame (`waterAt`, cleared as the fields begin, when the areas are whole), and a field continued over water never asks (`groundMatters`). **A pan over the world: 595 to 510 µs over water, 599 to 568 µs stopping at the shore; 48 to 42 allocations; a frame advance 560 to 529 allocations.** A first form that skipped the test only for a field over water made the shore case 3% slower (the per-dot check in the contour loop, which a CPU profile could not see past the runtime's own work); the memo makes both faster. With the guard ahead of it, `offItsGround`'s own over-water term could no longer change anything (mutant m001 survived), so it was taken out: one place decides |
| Each ramp built once (L-2.1) | `TestTheKeptRampsAreTheBuiltOnes` (`internal/colour`): every preset, ground and depth equal to its function's ramp; a caller's copy its own; a ramp token resolved with no allocation, where the old code allocated one each time | `rampDefault` reads the ramps in place, built the first time one is asked; `Ramp` still hands out a fresh copy |
| `Token.Name` names Wind explicitly | `TestTokensMatchTheDocumentedList`, unchanged | A token no case named was called "wind.N", a name `ParseToken` would accept; it is now nameless, which the list test catches |
| `presetGrid` | the preset tests, unchanged | `UVGrid`, `AirQualityGrid`, `MUFGrid`, `FoF2Grid` and `QPFGrid` are one line each over it |
| The mutant harness copies the tree once | `TestEveryMutantIsKilled` itself | It copied the tree (about 1,100 files) for every mutant; now once, each file put back from its saved bytes after its mutant and compared, a file not put back ending the run. Nineteen mutants in 21 s |

Mutants: m001, m004 and m005 re-pointed to the lines their rules now live on (m001 at `groundMatters`); m017, m018 and m020 new; every one killed by the harness. m005's first re-point left a variable unused, so the copy did not vet: the harness reported it INVALID, as it should.

**Safe ramps keep every preset's classes (D-29, D-5).** `TestSafeRampsKeepEveryScaleTheLibrarysOwn` (`internal/colour`), written first: over every token, a host's colour is passed over with safe ramps on exactly for an alert's colours and a preset's classes.
