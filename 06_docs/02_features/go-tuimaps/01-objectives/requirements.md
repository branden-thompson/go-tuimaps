Every requirement traces to a ruling, a finding, a brief item or a red-team finding. **Reading the "From" column:** D- is a ruling; L- a ledgered defect; AI- a research report; S*n*-*n* a specimen finding; P-58..P-67 (FR-26 only) parity rows; C-2 (NFR-14) a brief constraint. Bare A-, P-, S-, CQ-, PM-, BQ-, N- and X- codes are **round-1 red-team findings** (accessibility, performance, security, code quality, product, business, newcomer, cross-cutting) and are not the assumptions A-1..A-6 at the foot of this file. R2- codes are round-2 findings. IDs are stable and are **not** in numeric order; they are grouped by subject. Words a newcomer may not know are in the [glossary](glossary.md).

| FR-9 ▲ | Accept georeferenced images, each with a **required** colour-to-intensity table, and re-colour them with the library's ramp; a provider's own colours are never shown. | FR-11 ▲ | Simplify host shapes to the dot tolerance of the view. Shapes outside the view cost nothing to draw, and nothing is ever drawn outside the given rectangle. The simplified, *unclipped* result is cached per zoom bucket (buckets defined in PLAN; fractional zoom maps to one); on a miss, the nearest cached bucket is drawn while the right one is prepared, so a shape never vanishes mid-zoom. Simplification is iterative, never recursive; its worst-case bound is stated with the algorithm PLAN chooses — n·log n is a target, not a choice of algorithm. **Host geometry is borrowed, not copied:** the host must not change it while the overlay is set, and replaces it by setting the overlay again; this is documented and covered by a race-detector test. Borrowed bytes count against the *vertex* cap (NFR-20) only; bytes the library owns — simplified forms, indexes — count against the shape cache's byte cap. Where a bucket's simplified form would exceed a quarter of that cap (proposed), the library draws from the borrowed geometry with per-ring bounding-box culling instead of caching it. Only the simplified form is split at ±180° longitude; the convention is −180..180 and is stated. **One fill rule — even-odd — serves both the renderer and the description (FR-29).** Rings close implicitly; a ring with fewer than 3 distinct vertices is an error. | D-16, CQ-7, CQ-10, P-4, S-3, R2-CQ, R2-PF-A1, R2-IS-B6 |
| FR-12 | *(ratified by D-41, D-42, D-49)* Composite by a stated order: areas own the cell background (water, then images and fields, then tints); lines and glyphs own the foreground; labels sit on top. | specimens, cross-cutting 2 |
| FR-13 | Expose legend data — class breaks, their unit, and colours — for every overlay. | D-36, S1-6 |
| FR-14 | Report the credits in force, basemap and overlays together; draw an optional one-line credit on the map, on by default. | D-25, S9-1 |
| **Colour and theme** | | |
| FR-15 | Take a host palette covering basemap roles and overlay ramps (temperature's bands excepted — D-55); apply changes at runtime without re-parsing tiles; expose a change counter. | D-26, D-36 |
| FR-16 ▲ | Keep every ramp — default or supplied by a theme — **ordered** (relative luminance changes in one direction along the ramp, or on each side of a labelled midpoint for a diverging ramp), **distinct** (each step maps to a different palette entry at the colour depth in use) and **readable** (line work and glyphs at least 3:1, labels and legend text at least 4.5:1, against every cell background they are drawn on, by the WCAG formula). **The foreground is chosen per cell by computing both candidates' contrast and taking the higher** — not by a brightness threshold, which picks the worse candidate on some steps. **An area tint is never a shape's only edge:** a polygon's outline meets 3:1 against the ground it crosses and is not optional. A checker reports each violation; a host can run it in its own tests. **Colour-vision safety (D-53):** every *default* ramp, **at every colour depth the release supports**, keeps adjacent steps distinguishable under simulated protanopia, deuteranopia and tritanopia (threshold confirmed in PLAN); a *themed* ramp is run through the same checker and violations are reported, not refused. *The re-coloured radar ramp in the specimens fails this at 256 colours; a passing ramp is owed in PLAN. Whether users also get a "safe ramps" switch is R2-Q7.* **Temperature is not themeable (D-55):** it always uses the library's colour-vision-safe diverging ramp; a theme may adjust its line work and labels, not its bands. A scalar grid declares its kind so the library knows — *the closed set of kinds, the midpoint per unit and the default breaks are R2-Q6.* Every other overlay's ramp stays themeable. Legend swatches show the ramp actually drawn, with text chosen by the same contrast rule. | D-36, D-53, D-55, S1-3, S10-2, A-3, A-4, CQ-14, R2-AX |

## Non-functional requirements

| ID | Requirement | From |
|---|---|---|
| NFR-1 | Pure Go: the library, the app and every dependency build with CGO off, enforced by a cross-compile for macOS (arm64, amd64), Linux (amd64, arm64) and Windows (amd64). | D-22 |
| NFR-2 | Declare a Go version no newer than the first host's (1.25). | T-B, D-19 |
| NFR-3 ▲ | **Target (D-29): 8 MB.** Measured reproducibly against a **pinned fixture** committed to the repository. **The fixture (D-48):** one regional view; an alert overlay of 10 zone shapes, about 50,000 vertices; one single-frame radar image; one temperature grid — *its exact tiles, vertex count, image and grid dimensions are fixed in PLAN, and named in the test.* **Live** = the change in the runtime's live-heap metric after a forced collection, taken after a scripted tour that fills every cache to its cap — not after a first view. **Peak** = the maximum change in the runtime's heap-objects metric, sampled every 10 ms in a standalone harness, at the default collector setting. **Pass:** live ≤ 4 MB, peak ≤ 8 MB; default cache caps plus fixed buffers together ≤ 4 MB; decode concurrency is limited so the peak holds. The host's resident-memory protocol is confirmatory only, because its own run-to-run spread (8.5 MB) exceeds the figure being measured — *a change from the "added resident memory" D-29 named; HUM LEAD was told of it when D-48 was put, and the options file records the wording.* The embedded tiles (1.7 MB) are program data: invisible to heap metrics and present in the host's resident memory; stated here so it is not a surprise. Every cache — memory **and disk** — is capped by bytes with host-set caps. **Worst case, tested separately, at two named views (the fixture view and zoom 12):** a 58-zone, 812,058-vertex alert is accepted and drawn without the library copying the source geometry; library-owned bytes stay within the shape cache's cap by FR-11's rule; growth is bounded. Validated or revised at PLAN exit by measurement. | D-29, D-48, CQ-2, P-1, R2-PF-A1, R2-PF-A2 |
| NFR-4 ▲ | An unchanged frame makes **zero** allocations. Over a one-hour soak the live heap after collection grows by no more than 1 KB a minute (least-squares slope) and the count of goroutines at idle does not change. **A changed frame is the steady state, not the exception** — a blinking marker changes most frames — so it has a pinned test now and provisional numbers, revised only by ruling after the PLAN-exit measurement: Go benchmarks, floor toolchain, the D-48 fixture, 149×38, truecolor, tiles warm. *Provisional, unverified:* a marker-phase change ≤ 16 KB and ≤ 64 allocations; a one-cell pan no more than the first host's own window cost (765 KB, 1,346 allocations); identical counts at 100 and at 1,000 features. | D-29, CQ-14, P-3, R2-PF-A3 |
| NFR-5 ▲ | **Target (D-30):** the placed view within 1 s warm; within 3 s cold **to full detail**; a non-blank frame (FR-23's floor) from the first render call in both cases. Clocked from the host handing in its data; the clock stops at the first full-detail render under a simulated 300 ms host tick. Measured against a local test server **using secure transport**, shaped to a **stated link** — 150 ms round-trip latency, applied to connection setup as well; 8 Mbit/s in aggregate; no more than 6 connections — serving a pinned fixture (the four measured zoom-5 tiles, 1.2 MB). Validated or revised at PLAN exit. | D-30, BQ-5, P-5, R2-PF-A6 |
| NFR-6 ▲ | Render is a pure function of the view, size, colour depth, palette, the time supplied, the overlays and the **ordered set of tiles on hand**. Tiles are visited in a fixed order; nothing depends on map iteration order or on which fetch finished first. Reference frames are byte-identical on amd64 and arm64, **shown by running the reference-frame tests on both** — cross-compiling proves nothing here. Where a product feeds a sum, an explicit conversion prevents the fused multiply-add that arm64 would otherwise apply; non-finite values never reach a float-to-integer step. | AI-4 §9, CQ-11, R2-CQ |
| NFR-7 | macOS, Linux and Windows; UTF-8; usable from a 69×12-cell rectangle; safe over SSH, with nothing that depends on querying the terminal. | D-23 |
| NFR-8 ▲ | Every line of a frame is exactly the requested width under one pinned width table — the same one the first host measures with, **under the fixed narrow condition** (ambiguous-width characters count as one column). Every character the renderer itself emits comes from a closed list checked against the Unicode width data: braille is neutral width and safe; block, box-drawing, shade and arrow characters are *ambiguous* width and are verified against a matrix of supported terminals **at PLAN entry**, before any design depends on them. Text is handled by grapheme cluster (FR-34): a cluster occupies one or two cells by the table, and one that does not fit is dropped whole. *The closed list for v0.1.0 is: space, braille, the marker glyphs, box-drawing for the scale mark, the hatch stroke, and block shades for no-colour images (D-57).* | AI-3 §6, S2-2, S3-3, CQ-6, A-7, R2-CQ |
| NFR-9 ◆ | Dependencies are an explicit allow-list; each carries a licence file. A vulnerability scan of the module **and of the standard library at the toolchain in use** gates every change and runs weekly; releases are built with the latest patch toolchain, scanned as binaries, and ship with SHA-256 checksums. No `replace` directive in the module file. *The allow-list's contents are a PLAN decision.* | D-13, X-5, S-7 |
| NFR-10 ▲ | **Everything that arrives from outside is untrusted**: compressed bodies, vector tiles, TileJSON, PMTiles headers, directories and metadata, style files, images, and feature input. Limits are **defaults, not proposals** — tests come first, so the numbers are fixed here — enforced **before allocating**, host-settable: tile body ≤ 2 MiB, decompressed ≤ 8 MiB; **per tile, layers ≤ 64, features ≤ 100,000, geometry integers ≤ 2,000,000, retained bytes ≤ 4 MiB, refused over any limit** (checked against real maxima across zoom 0–14 in PLAN; the measured maxima so far cover zoom 0–3 only); PMTiles directory ≤ 1 MiB decompressed, **entry count ≤ the lesser of a quarter of the bytes remaining and 65,536**, leaf depth ≤ 3 with a cycle guard, every offset and length checked for overflow and against the file size; metadata, TileJSON and style ≤ 1 MiB, nesting ≤ 64, reference and constant cycles detected; any other count ≤ the bytes remaining divided by its smallest encoding; tile extent 1..65,536; compression other than none or gzip, and any non-vector tile type, returns a clear "unsupported" error; image limits are FR-9's. Every decoder is fuzzed — at least 60 s per target on every change and an hour before a release — never panics, and crashers become permanent test seeds. | RS-12, S-2, CQ-3, R2-IS-B4, R2-CQ |
| NFR-11 ▲ | Automated tests connect to the loopback address only, enforced by a dial hook that fails the test otherwise; examples are tested against committed recorded fixtures. The tile generator (FR-28a) is the one tool that reaches the network, and only when run deliberately. | D-30, R2-IS-B9 |
| NFR-12 | The library never bulk-downloads or prefetches from the public tile server. | D-21 |
| NFR-13 | MIT licence; both upstream notices carried; OpenMapTiles and OpenStreetMap credited; the embedded data carries its own notice. | D-13, D-25, D-33 |
| NFR-14 | Sole-author commits; no tool-generated trailers or watermarks. Local development tooling stays untracked. | C-2 (brief), D-7, D-50 |
| NFR-15 ▲ | Accessibility: nothing reachable by pointer only, shown by a scripted keys-only session that reaches every state a pointer session reaches; legible with no colour, shown by a reviewer answering the M1 questions from the no-colour reference frames alone; with no depth hint from the host, a non-empty `NO_COLOR` selects the no-colour depth. A non-visual description of the view is FR-29 (D-52), reachable in the app through FR-5's describe mode. Ramp safety is FR-16 (D-53, D-55); motion is NFR-21 (D-56). *Light-background terminals are R2-Q8.* | D-17, D-23, D-35, D-52, A-6, A-7, R2-AX |
| NFR-21 ✚ | **Motion is safe and optional.** Nothing flashes faster than 2.5 times a second. A reduce-motion setting draws markers in a steady "on" form, makes camera moves jump, and stops all animation; a host can set it and the app honours the terminal convention where one exists. A frozen clock never hides a marker. The on-map credit never disappears on a timer alone. | D-56, A-5 |
| NFR-16 ◆ | Tests first for all Go code, run with the race detector; the code-quality gate is declared and green from BUILD entry; builds use the floor toolchain (Go 1.25) with read-only modules, so an API newer than the first host's cannot slip in. | FULL TDD, D-20, CQ-12 |

| **Asynchronous work** | | |
| FR-30 ▲ | **Who runs background work is explicit, bounded and leak-free.** Whatever model PLAN chooses (PLAN proposes at least two, compared in a named design note: host-scheduled blocking calls; a small library-owned pool), it meets all of these: every goroutine has a stated owner and none outlives the map instance (leak-tested); in-flight fetches and the simplification backlog are capped, newest view wins; every job takes a context and is cancelled when its tile or shape leaves the view; one render may run while one fetch runs, shown under the race detector; completion moves the change counter and keeps the next-change deadline (FR-25) current so an idle host still redraws; an optional callback lets a host be told rather than poll. A *settle* call waits for pending work — which is how the headless render (FR-4) produces a complete frame without breaking FR-23 — **and always ends**: it takes a context, returns when nothing is pending or the context ends, and says which; work that failed and is in back-off is not pending. No panic escapes a public call or a library goroutine. | CQ-1, P-2, S-3, R2-CQ |
| FR-31 ✚ | The tile cache never serves a tile parsed for a different style profile or label language: either the key includes them, or tiles are decoded without reference to style. | CQ-8 |

| FR-37 ✚ | An image overlay may carry a **sequence of timed frames**, played on the host's clock (FR-25), with the frame count held inside the image cache's byte cap. *In v1; designed with the contract in PLAN; built after v0.1.0 (D-47). v0.1.0 shows the latest frame.* | D-47, PM-6 |
| FR-29 ▲ | **Describe the view, as data, for each place the host names.** For every overlay kind: *areas* — inside or outside, with distance and compass bearing to the nearest edge; *points and lines* — distance and bearing to the nearest, with its label; *fields* — the value with its unit, its band, and which way it rises; *images* — the intensity class here and the nearest heavier class with distance and bearing; and for each overlay its valid time, **whether it is stale, and "no data here" said plainly** where that is the case. Distances are great-circle; longitude is circular, so a seam at ±180° is never reported as an edge. Units follow the host's setting (metric or US customary, °C or °F) and are always stated. Computed from the borrowed shapes and the data by FR-11's fill rule, never from the drawn cells, so picture and description cannot disagree about which side of a line a place is on. Deterministic; no braille, block or box-drawing characters; speakable — values with units, compass words, no abbreviations a speech engine would spell out. **Cost:** never computed inside Render; recomputed only when overlays, places or staleness change; cancellable (FR-30); any index counts against the shape cache's cap; *provisional targets, unverified:* the fixture with 60 places ≤ 50 ms, the worst case ≤ 500 ms, an unchanged repeat allocates nothing. The host renders or speaks it; the app prints it (FR-5). **Acceptance, in v0.1.0:** with the specimen-4 data the description says the place is inside the flood warning; every M1 scenario *in the v0.1.0 slice* has a description that matches the answer key. **The answer key is computed independently of this code** — by a separate reference script over the same data — so the check is not circular (D-43). | D-52, A-1, PM-7, R2-AX, R2-BZ-A2, R2-PF-A4, R2-IS-B6 |
| FR-32 ▲ | **Every overlay carries a valid time, and the map can show when data is old.** The host states when each overlay's data was valid and how long it stays current (more than zero, at most 7 days); the library exposes that beside the legend data (FR-13) and can mark an overlay stale on the frame. Weather freshness is the one kind that matters (D-18). | PM-6, R2-IS-B7 |
| FR-33 ▲ | **A distance reference.** The library exposes the ground distance one cell spans at the view's centre — **across a column and down a row separately, since they differ** — and can draw a scale mark, so "roughly how far" (M1) has an answer. Fuzzed, on both paths, so that no input produces an escape byte outside the library's own colour sequences. | S-1, CQ-3, R2-CQ, R2-IS-B1 |

| FR-21a ▲ | The disk cache has a host-set byte cap (default 256 MB) and evicts by least-recently-read, never by age — consistent with "no expiry" (D-18). **Recency is portable:** the library sets a file's modification time when it reads it, at most once an hour per file; the running total is kept in memory, seeded by one walk when the cache is opened; pruning brings the cache to 90% of the cap, off the drawing path. | P-6, CQ-3, R2-CQ, R2-PF-A7 |
| FR-21b ▲ | **The disk cache is off unless the host configures a root** — its file names are a record of where the user has looked. Cache paths are built only from a hash of the source identity and integers the library formats itself; all cache file access is confined to the cache root; directories are private to the user, files likewise, written by temporary file and rename; a cache root writable by others is refused where the platform can tell (on Windows the root lies under the user's profile and the check is documented as not performed). The app offers no-cache and purge (one source or all), and the README says what is sent, to whom, and what is stored. | S-5, R2-IS-B8 |
| FR-22a ✚ | A tile is written to the cache **only after** a success status, a length within limits and a complete successful decode. A cached file that fails to decode is deleted and fetched again. The cache key is the full source identity (for a remote archive: its entity tag and length). `Purge` and `Verify` are exposed, and offered as flags in the app. | S-4, L-2 |
| FR-22b ▲ | Secure transport by default; plain `http://` only by explicit option or on the loopback address. At most 3 redirects, never from secure to plain, never to another host unless allowed, never into loopback, link-local or private address space unless the configured source is already there — **checked against the address actually connected to, at dial time**, and documented as unenforceable behind a proxy; the same for tile addresses read from TileJSON. No Referer is sent. **A tile address may hold a key, so it never appears in error, warning, description, credit, User-Agent or path text; errors name the scheme and host only.** Every response body is read through a limit. A range reply that is not a 206 with exactly the requested range is closed unread. The replacement fetcher's contract carries the range and the maximum length, and the library checks what comes back. **No connection is ever made unless the host configured a network source** — *whether the library's own default counts as "configured" is R2-Q9.* The User-Agent names the library and version and a host-supplied token, never the operating system, host name or user. Proxy settings from the environment are honoured. | S-6, AI-9 §8, R2-IS-B2, R2-IS-B3 |
| FR-28a ▲ | The embedded tiles pin the planet file by version, length and entity tag; a SHA-256 list of every source tile and every output tile is committed; pin, hash list and asset change only together; continuous integration re-hashes the asset and decodes every embedded tile through the hardened decoder. The hash list proves the asset is unchanged since it was generated, not that the source was authentic; that is said in the data notice. The generator is written in Go, lives in the repository, and fails on any range reply but a 206. *It must read a single-file archive, and the archive reader is deferred past v0.1.0 — how that is squared is R2-Q2.* | S-7, BQ-6, R2-BZ-B2, R2-IS-B9 |
| FR-35 ✚ | **The tile schema is a seam.** Layer and attribute names a style depends on are resolved through one replaceable mapping keyed on the source's declared layers, so a change of schema by the provider is a new mapping, not a new renderer. | PM-5, AI-2 §5 |
| **Newcomers and host mistakes** | | |
| NFR-17 ▲ | A runnable, continuously tested example for each input shape lives under `examples/`, outside the library's contract — including radar from one keyless source **with its complete, tested colour-to-intensity table**, which a newcomer can copy. **In v0.1.0 the radar example uses the image shape** — one image for one bounding box — because tile-image providers are deferred; every radar specimen so far fetched tiles, so this path is not yet demonstrated (*one bounding-box request was tried in round 2 and the service was unavailable; confirming a source is a PLAN-entry item*). | NFR-19 ▲ | **Counts that can be met, and are stated.** A world map in a rectangle, with the assets package imported and no network: no more than 3 calls. A first *feature* overlay: one more. A scalar grid additionally names its kind and breaks; an image additionally supplies its table — the example table is one import. A network basemap is one further, explicit call (FR-22b). Everything else is defaulted, including a ramp per colour depth. The example tests compile with exactly those calls, and the README states each count. | N-4, R2-NC |
| NFR-20 ▲ | Every value a host hands in is validated on hand-in: non-finite or out-of-range coordinates, grid sizes that do not match their data, unsorted class breaks, a missing or malformed table (FR-9), a ring with too few vertices (FR-11), a currency period out of range (FR-32), a ramp that fails FR-16, an overlay over its size cap (**default 2,000,000 vertices per overlay and 4,000,000 per instance**, host-settable). A tile source whose declared layers match no known mapping returns an "unsupported schema" error (D-46, FR-35). A failure returns a typed error from a **closed, documented list of kinds**, saying what happened, why, and what to do, and never quotes a tile address (FR-22b); a table-driven test hands in each likely mistake — a missing or stale table, latitude and longitude swapped, a grid that does not match its data, unsorted breaks, no tile source and no assets, a render without settle, not-a-number used as "missing", an under-size rectangle, calls from several goroutines — and checks the message against a reviewed text. Non-fatal problems are retrievable as a list — at most 64, de-duplicated — and through an optional callback. The library never writes to standard output or standard error. **Every exported name carries a doc comment, and the README lists what is deferred and what v0.x promises about compatibility** (*the promise itself is R2-Q4*). | N-5, S-3, D-46, R2-IS-B5, R2-IS-B8, R2-NC |
